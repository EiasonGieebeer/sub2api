# 密钥与用量

## API Key 管理

在[「API 密钥」](https://sub.fastapi.cool/keys)页面创建和管理密钥。推荐：

- 开发、测试和生产环境分别使用不同密钥；
- 为每个应用设置独立额度和有效期；
- 生产服务配置 IP 白名单；
- 不定期轮换密钥；
- 怀疑泄露时立即禁用或删除，而不是等待客服处理。

## 查看用量

[「使用记录」](https://sub.fastapi.cool/usage)提供请求明细和统计信息，包括请求 ID、请求类型、模型、Token、费用、状态、耗时及请求时间。管理员视图在对应记录存在时还会区分请求模型、发往上游的模型和上游响应模型，并可筛选响应模型是否一致；日期版本差异可能被标记为“疑似版本变体”。该审计信息用于排查路由结果，不改变最终扣费依据。分组用量摘要可分别展示今日、昨日和累计费用，统计边界以服务端配置的时区为准。

公开的[密钥用量查询](https://sub.fastapi.cool/key-usage)可用于查询指定密钥状态。不要在不可信设备或网页中输入密钥。

## 查看渠道和服务状态

可先通过[「模型广场」](https://sub.fastapi.cool/model-plaza)了解公开的模型、分组与价格。模型广场可能由管理员关闭或要求登录，且展示内容用于选型参考。

登录后可在[「可用渠道」](https://sub.fastapi.cool/available-channels)查看当前账号可访问的渠道、分组、模型和价格信息。该页面展示的是当前账号视角下的可用范围，不等同于全站所有后台渠道；实际调用能力以 `/v1/models` 和当前 API Key 为准。

[「渠道状态」](https://sub.fastapi.cool/monitor)用于查看管理员公开的渠道监控结果、近期可用性和延迟。管理员可选择 v1 主动探测，或显式切换到 v2 被动聚合；v2 会基于真实请求逐步生成成功率、首 Token 延迟、Token 速率、缓存率、趋势和错误分类，首次启用时历史范围会渐进回填。v1 监控还可由管理员选择“探活”“配额”或“配额 + 探活”模式，并关联已有账号获取滚动窗口、重置时间或多币种余额；支持范围取决于平台和账号类型，例如 Antigravity 只支持配额模式，部分 API Key 账号没有上游用量通道。

出于隐私考虑，管理员可隐藏 RPM/TPM 吞吐信息。用户端配额/余额展示也默认关闭且由服务端剥离，只有管理员显式开启 `channel_monitor_show_quota` 后才会公开；管理员视图仍可见。若某个模型突然不可用，先确认渠道状态、模型范围、订阅/余额和密钥限制。

上述监控模式、公开范围和吞吐显示均是管理员配置项；功能关闭时页面或接口可能不可用，不能据此认定实际模型一定不可调用。

## 额度和限流

调用可能同时受到以下限制：

- 用户余额或订阅额度；
- API Key 自身额度；
- 用户、分组或上游账号并发；
- RPM、TPM 或上游动态配额；
- 模型、IP 白名单和有效期限制。

收到 `429` 时应降低并发并指数退避；收到 `402` 时检查余额和订阅；收到 `403` 时检查模型、分组和 IP 设置。

## 安全建议

API Key 等同于调用凭证。不要写入前端 JavaScript、移动应用安装包、公开 Git 仓库、截图和工单。服务端日志应只记录密钥前后少量字符或不可逆摘要。

账户登录建议启用 TOTP 二次验证。如果[「个人资料」](https://sub.fastapi.cool/profile)中提供 Passkey（通行密钥），可在受信任设备上完成绑定；新增或删除 Passkey 需要验证当前密码。不要在公共设备上绑定 Passkey，设备丢失后应及时移除对应凭证。
